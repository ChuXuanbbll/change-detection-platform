# 管理与配置

按 2026-10-12 的 `management.go`、`admin.py` 和 `settings.py` 核对。此文描述当前行为；未来扩展见 [开发待办](ROADMAP.md)。

左侧第四个入口「管理」包含模型、影像来源、检测默认值、性能与诊断。编辑不等于生效：点击「校验配置」检查目录与参数，点击「应用配置」发布新版本；只有 Go 和 Python 确认同一版本，页面才显示「已生效」。操作失败保留旧版本，可查看错误后重试。

## 设置来源与迁移

首次启动在现有 `meta.db` 增建 `config_revisions`、`managed_models`、`config_operations`、`config_batches`，不会搬迁或删除影像、结果和原表。影像目录与瓦片运行参数从启动环境迁移；检测默认值为阈值 0.5、分辨率 0.8 米、核大小 3、最小面积 10 像元，GPU 0、推理批大小 1、预取 2、超时 3600 秒、检测并发 1、队列容量 128。完整字段约束以 `backend-py/app/settings.py` 为准，瓦片默认值见 [瓦片说明](tile-loading.md)。

之后业务配置以 SQLite 为准。改变旧环境变量不覆盖已持久化设置。端口、Python 解释器、CUDA DLL 搜索目录、数据库位置、边界资源位置仍由部署环境指定，仅提供只读诊断。

首次模型登记处于未验证状态，前往「模型」点击「验证 CUDA / 映射」。无有效 GPU、模型不兼容或影像盘不可访问时，服务仍提供管理入口；不会自动换模型或使用 CPU 假装执行成功。

保存携带 `expected_revision`。其他标签页已保存时，返回版本冲突；先重新加载再编辑。历史回退创建一个新的生效版本，保留任务、结果和模型引用。服务中断后未完成操作记为失败，恢复已提交版本；Python 单独重启后可在管理页「重新同步」，同步之前拒绝创建新批次。

## 模型

可上传 ONNX 文件，也可填写**服务端**绝对文件路径导入。上传不是填写浏览器电脑上的文件路径。文件流式写入 `DATA_DIR/models`，以 SHA-256 标识内容，同内容复用制品，不覆盖已有模型。上传大小由部署参数 `upload_max_mb` 控制（默认 2048 MiB）。路径导入也需要服务进程有读取权限。

支持内嵌权重的单文件 ONNX。输入为一个六通道或两个三通道 NCHW 浮点张量，512×512；前后 RGB 使用现有 ImageNet 归一化。输出为单通道变化 logits，或双通道 logits 中第 1 类为变化。多输入/多输出需要明确映射。固定批大小以模型要求为准，动态批大小使用配置值。

验证包括 ONNX 结构、哈希、映射、输出维度和真实最小 CUDA 推理。**不证明精度、归一化训练协议或类别语义正确**，模型提供方必须确认这些契约。外部权重、错误维度、映射和 CUDA 失败会保留具体诊断，禁止启用。停用不影响已冻结的批次。被配置历史或批次引用的模型只能停用；移除未引用登记也不自动清除制品文件。

在概览右栏选择本批次模型。提交裁切时冻结模型 ID、SHA-256、输入输出映射、配置版本、GPU 参数和最终检测参数。后续相邻组只读取该快照；客户端再传参数也不能改变本批次。执行前校验模型文件哈希。

## 多目录影像

目录指向服务主机本地盘或 UNC 共享盘。每个来源有稳定 ID，可设置名称、年份、启停、顺序。未指定年份时从年份根目录解析，月份只按 `1月` … `12月` 目录，不从文件名猜测。保留既有 `catalog.json` 清单作为迁移兼容入口。

影像 ID 带来源前缀，相同文件名不会跨年份或目录冲突。同区域同月合成一个时相：真实分辨率较细的有效像元优先，同分辨率按来源顺序，再按相对路径。展示瓦片和检测裁切共用拼接函数。单文件损坏保留不可用诊断；启用目录不可访问、目录重复或重叠时，应用失败，不发布部分来源。

来源/顺序变化更新合成版本和缓存键，旧版合成瓦片返回过期状态。运行中的页面批次结束后才刷新选择与浏览器缓存；浏览器获得焦点时检查配置变化。原始影像永不由配置操作删除。

## 性能与诊断

- 检测参数：新批次使用，右栏可覆盖。
- GPU、推理批大小、预取、超时：记录在批次快照，推理子进程使用。超时终止该任务拥有的进程树。
- 检测并发和队列容量：实际控制 Go 队列；改变限制要求队列空闲，忙时明确拒绝。
- 瓦片进程、队列、等待时间、PNG 缓存、句柄和 GDAL 缓存：先准备新进程，成功后切换，排空旧进程。
- 浏览器请求并发、非活动时相数、容量和闲置时间：重建相关缓存；当前批次中延后重建。

诊断中的 `cuda_verified` 为最近一次实际 CUDA 试运行结果；`null` 表示尚未验证，不把 provider 环境变量当成可用证明。服务重启后需要再次探测，任务执行也会检查 CUDA 是否真正启动。

## 边界

管理面向本机单人使用，不是多用户权限系统。原生服务与 Vite 默认仅绑定回环地址，管理入口检查连接来源、Host、Origin、请求类型。Go→Python 控制请求使用运行目录内随机令牌；浏览器不可访问 Python 管理路由。Docker 附带的回环发布、入口地址限制和私有代理令牌必须一起保留，不能擅自把发布地址改为 `0.0.0.0`。

批次仍由浏览器编排。切换四个页面不打断检测；刷新或关闭页面会丢失后续组编排，当前已提交任务继续执行，已有结果留在数据库和文件中。
