### 1.2 用户已确认的方向

- **目标：** 在明确任务范围内，AI 自主完成绝大多数已接口化的平台操作，并根据执行结果调整步骤；用户主要提供目标和关键取舍。
- **自主性：有界自主探索。** 允许在明确的区域、时间和计算预算内进行多组实验、结果比较与失败恢复；改变关键研究条件时再询问。
- **视觉能力：纳入整体设计，分阶段实现。** 先打通操作与持续工作流，为影像查看、对象定位和辅助选区保留清晰接口。
- **直接痛点：** 助手无法灵活修改框选、组织多个时相互相比较，早期版本的操作自由度更高。需要解释并修复能力接口与编排缺口，不能把所有失败归因于模型。

这些确认不等于授权立即开发全部功能，也不表示预算数值、视觉模型、评价指标、具体接口和实施排期已经确定。本轮实施范围仅为文档。

### 1.3 代表性目标与成功形态

> 把当前选区向东移动 100 米，以 1 月为基准比较其他月份；检查变化异常大的时段，完成后排序并导出前三组。

该任务贯通选区编辑、资源发现、配对计划、批量执行、结果核查、集合统计与导出。预期助手能够读取当前状态，调用几何工具完成平移，验证可用月份与覆盖，生成明确配对，提交并持续跟踪整组任务，再核查异常、排序和导出。

“变化异常大”的判据、“前三组”的排序口径以及允许追加的验证计算，需要有任务约定或说明清楚的默认依据，不能在结果出来后任意改写。用户不应被迫逐个搬运任务 ID、逐组打开结果或保持页面开启来驱动后续提交。

自主性体现为执行过程中根据结果决定下一步，不要求开始前一次性猜出全部步骤。实现步骤可以调整；明确指定的研究条件必须保留。

### 2.2 为什么收敛，以及为什么仍需扩展

[历史修复记录](ai-assistant-review.md) 记录过时相误选、重复选择区域、工作区版本过期、无关地图操作、重复准备状态查询，以及没有有效提交却可能以文字结束为成功等问题。当前共享提交入口与版本回执、重复提交保护、结果引用检查共同解决了这些问题；不能把所有改善都归因于单一入口。

让 AI 与页面按钮共用业务入口是合理的。问题在于简化检测路径时，选区操作等能力被移除，却没有补上独立的工作区编辑能力。当前助手更接近几个预设流程的入口，而非可组合完整工作区能力的执行者。

> 应保留共享业务入口的可靠性，并补齐独立操作与灵活编排能力；不建议简单恢复全部底层调用链，也不能只靠放宽提示词或提高调用次数解决。

### 2.3 编排层的限制

当前路径包含 Skill 选择、固定槽位解析、所选 Skill 工具白名单、前置条件校验和执行。普通意图最多包含四个操作，每个操作有自己的权限和调用预算，见 [意图定义](../backend-go/internal/ai/intent.go)、[执行网关](../backend-go/internal/ai/gateway.go) 和 [前置条件实现](../backend-go/internal/ai/skill_execution.go)。

这些机制有保护价值，但组合后会出现：工作区编辑没有完整意图出口；执行中发现缺少能力时难以自然补充；早期槽位解析丢失的信息难以补救；跨操作输出主要是单个任务而非资源集合。应分别改进意图表达、能力获取、资源引用和持续执行，不能只解除一个限制就认为整条链路已经自由。

### 2.4 证据范围

本轮依据为源码检查、历史提交比较和既有修复记录，没有重新运行真实云端模型、浏览器验收或真实推理。历史确定性夹具通过不证明真实语义识别成功率、耗时、费用或遥感精度；当前源码也不能证明运行中的服务已重启加载。本文不提供未经测量的成功率或性能承诺。

## 3. 建议方案 / TODO：能力实现

本节全部为建议，不是已确定的 API 命名、传输结构或上线能力。

### 3.1 职责分工

| 层次 | 建议职责 |
|---|---|
| AI | 理解目标、选择方法、组织实验、根据结果调整步骤、解释结果 |
| 业务工具 | 几何变换、时相配对、检测提交、结果筛选、统计与导出 |
| 工作流服务 | 保存目标和运行状态、等待任务、推进后续步骤、取消与恢复 |
| 界面 | 展示状态与修改结果、接受人工调整、提供撤销和运行控制 |

模型负责意图与决策，确定性代码负责几何、单位、投影、组合生成和统计。例：“向东移动 100 米”应转换为有对象、有方向、有距离单位的操作，由工具计算新几何并校验，不能让模型手算一串经纬度。

工具以完整业务动作划分，不机械地一一映射每个 HTTP 接口。适合独立组合的操作开放为独立能力，裁切准备、状态等待等重复步骤可以由业务服务封装。继续保留资源校验、输入输出契约、状态版本、幂等和执行回执。

### 3.2 工作区操作

- 选区创建、替换、平移、缓冲、缩放、清空、撤销；对变换前后几何提供可见反馈。
- 时相添加、移除、替换，以及当前显示对象和比较对象切换。
- 选择已有可用模型，修改本次实验参数；与修改模型文件或全局配置区分。
- 选择结果、筛选图斑、定位变化区域和导出。
- 将上述能力从“执行检测”中分离，避免为了改参数、改选区或看影像而被迫提交任务。

已有单 Polygon 校验和几何工具可作为基础。平移、缓冲及缩放必须明确坐标系、距离或比例、基准点和覆盖情况；具体缺省规则尚待接口设计。不能把用户要求的几何变换偷偷改成裁掉无覆盖部分或扩大包围盒。

### 3.3 动态组合与恢复

Skill 提供推荐方法和领域知识，权限由能力与资源规则控制，避免将 Skill 变成互相隔离的功能岛。执行中允许按当前目标获取必要能力、补查资源、修正调用并调整剩余步骤。

自主恢复应保留已完成步骤和已验证结果，不能重新播放整个操作链。状态过期时重新读取并判断目标是否仍成立；不能只更新版本号后盲目重试。任务是否已提交不明确时，先核查状态，避免重复计算。

### 3.4 明确的多时相比较计划

| 策略 | 例子：1、3、5、7 月 |
|---|---|
| 首尾比较 | 1→7 |
| 相邻比较 | 1→3、3→5、5→7 |
| 固定基准 | 以 1 月为基准：1→3、1→5、1→7 |
| 全部两两 | 1→3、1→5、1→7、3→5、3→7、5→7 |
| 显式清单 | 用户指定 1→5、3→7，仅执行这两组 |

提交前生成实际日期和明确配对清单，验证数据、日期精度与空间覆盖，并估算工作量。12 个时相全部两两比较产生 `12 × 11 / 2 = 66` 组时相组合；实际任务数量还取决于影像组织与处理策略。

不得用排序后的相邻配对替代任意指定配对，也不能把两个指定月份改成区间内所有月份。缺失月份必须说明，不伪造影像或静默替换日期。展示计划不等于每次强制审批；任务约定内的明确请求应可直接执行。

### 3.5 持续执行与集合结果

服务端保存任务目标、计划、资源快照、执行进度和结果引用，负责后续组的推进。AI 不必持续占用一次模型调用或让浏览器不断轮询来保持业务前进。

支持等待完成、失败组重试、整批结果查询、统一筛选与导出。上一操作应能提供任务集合或运行引用，下一操作据此处理整组资源；多个结果本身不应成为必须向用户澄清的理由。只有“需要单个结果但目标无法唯一确定”等真实歧义才需要选择。

当前用于冻结配置和模型的 `batch_id` 与持久化工作流含义不同；应明确两者关联，不能仅复用名称就认为具备持续执行能力。已经提交的检测与尚未执行的后续步骤要分别追踪。

取消语义至少区分“停止 AI 后续编排”“取消剩余组”“取消正在运行的检测”。停止聊天不等于 GPU 任务已停止。具体取消保证和服务重启恢复范围仍待决策。

### 3.6 运行快照与当前地图分离

建议在提交时冻结区域、时相配对、模型和参数。用户之后修改地图，默认影响下一次操作，不污染已经运行的实验，也不必因后台检测而一直锁住整个工作区。

修改运行条件通过明确的取消、追加或重新运行表达。结果保留原始条件以供对照；可逆工作区操作提供反馈与撤销，不引入逐步确认流程。

### 3.7 有界实验与评价

任务约定应描述使用哪些数据、研究哪些区域和时间、允许尝试哪些参数、在什么预算内追求什么目标。范围内的查询、编辑与实验可自主执行；超过范围时再请求用户取舍。

“优化一下效果”不能直接转化为反复调参直到检测面积更大。需要区分有标注的指标驱动实验和无标注的稳定性、敏感性分析。预算单位、默认值、评价依据和终止条件尚未确定，不在本文中虚构。

### 3.8 视觉能力分阶段接入

1. 查看指定区域、指定时相的影像切片，保留时间、分辨率、覆盖范围及空间定位信息，能引用观察位置。
2. 根据影像提出候选选区，叠加地图供查看和调整；区分候选、人工修正和最终采用的几何。
3. 结合定位、分割或专门模型开展对象级分析，并根据实际验证结果说明适用范围。

“向东移 100 米”依赖几何工具；“框住图上那片新建厂房”还依赖影像感知与空间定位。增加操作 API 不能自动补齐后者。

仅发送地图截图不足以保证定位正确，必须保留像素与地理坐标关系。模型描述了对象不等于对象地理定位准确。视觉数据能否发送至外部模型服务、发送范围及脱敏要求应先确定，不能从接入视觉能力自动推定。

## 4. 能力边界与分析规则

### 4.1 应保留的执行边界

- 源影像和模型文件只读；修改派生选区、选择已有模型与调整本次参数不等于修改这些源资源。
- 禁止虚构资源、日期、坐标、任务状态和结果；坐标变换应有工具计算依据。
- 不重复提交已成功或状态尚未确认的计算任务，不以成功文字代替工具证据。
- 对无效几何、无覆盖、资源冲突和过期状态说明实际原因及可采取的动作。
- 保留类型化领域接口，不通过通用 shell、SQL、任意文件或任意 HTTP 接口绕过业务边界。

### 4.2 任务约定边界

**可以自主决定怎样完成目标，不应擅自改变研究目标与明确条件。**

- 在约定内调整实现步骤、补查资源和恢复失败，不随意改变指定区域、日期或评价目标。
- 平移后无覆盖不能偷偷反向移动；某月无影像不能静默换月；用户指定配对不能改成另一种策略。
- 超出预算、引入新数据来源或改变关键研究条件时请求用户选择，避免无必要的逐步确认。
- 调用次数只作为防循环的技术保护。业务预算应考虑任务组数、像元量、时间与资源消耗；十次查询和十次大范围推理不是相同成本。

### 4.3 结论与证据边界

| 分析事项 | 应遵守的规则 |
|---|---|
| 效果与面积 | 检测面积更大不代表更准确，不能将“检出更多”自动作为优化目标 |
| 模型分数 | 分数不自动等于经过校准的正确概率，应沿用实际模型输出含义 |
| 多期汇总 | 变化面积不能直接累加，同一区域可能多次变化或反复变化 |
| 跨组排名 | 有效覆盖不同的结果不宜直接按变化总面积比较，应先核查覆盖与统计口径 |
| 有标注实验 | 在明确指标和适用数据范围内自动调参、对照并比较，结论仅覆盖实际评估范围 |
| 无标注实验 | 分析敏感性、稳定性与异常，不能宣称获得最高准确率 |
| 解释 | 区分统计事实、模型预测、视觉观察与解释性推测，附对应证据或限制 |
| 业务定性 | 违法建设等结论需要土地用途、审批等额外证据，不能由变化掩膜或视觉描述直接推导 |

例如，可以报告“这组参数的结果对小幅调整更稳定”，不能在没有标注评估时将其写成“这组参数准确率最高”。

### 4.4 可演进的功能限制

单 Polygon、无孔等约束属于当前功能限制，应与永久执行边界分开。多选区、孔洞、MultiPolygon 可另行评估扩展，但必须贯通几何验证、裁切、推理、统计与导出，不能静默转成外接矩形。扩展阶段仍待确定。

### 5.1 完整链路场景

| 场景 | 拟定验收结果 |
|---|---|
| 代表性完整任务 | 完成选区平移、固定基准比较、异常核查、明确口径排序和前三组导出；中间不要求用户手动传任务 ID |
| 缺失月份或日期精度不符 | 说明实际数据与限制；不伪造日期、不静默替代月份 |
| 平移后无覆盖、非法几何 | 明确失败原因，保留可恢复状态；不擅自反向移动或改成包围盒 |
| 参数冲突、人工编辑或旧状态命令 | 重新核对当前状态与明确目标，不能覆盖用户新修改或仅换版本盲重试 |
| 重复提交、超时或回执不确定 | 核查已经创建的任务，避免重复计算，不把未确认状态当成功 |
| 多组检测部分失败 | 保留已成功组及其条件，允许按授权重试失败组；汇总标明缺失和失败 |
| 停止与取消 | 停止编排、取消剩余组及取消正在运行的检测，效果与界面表述一致 |
| 页面关闭与断连 | 服务端继续推进约定流程；恢复后展示真实进度，不重放已完成副作用 |
| 开放目标与预算耗尽 | 在约定指标和预算内探索，耗尽后报告已获得结果与剩余事项，不偷偷扩大预算 |
| 无标注、多期重复变化与覆盖差异 | 不伪报精度，不直接累加重复变化，不以不可比的面积误导排名 |
| 视觉候选选区 | 影像时相正确，像素与地理位置对应，候选几何可见、可修正且有来源 |

服务重启恢复范围、取消进行中计算的保证先确定，再增加对应故障注入与恢复验收。真实模型验收应包含自然表达的变体和组合请求，分别记录理解失败、工具失败与业务执行失败；不在没有样本和测量时给出成功率。

### 5.2 验证层次

契约和确定性算法测试验证输入、几何、配对、幂等与统计；隔离浏览器测试验证 UI 状态、人工编辑、回执与断连；真实模型验证语义、能力选择和解释；真实影像与推理验证业务链路及统计；视觉验证额外检查定位和对象分析。各层证据分别报告，不能因前端构建或夹具通过而宣称真实任务已验证。

## 6. 可行性与建议阶段

以下是工程判断，不是工期承诺。前两类能力主要涉及接口和编排，不要求替换现有检测模型；持续执行需要调度职责变化；视觉能力需要新增感知与定位支持。

| 能力层次 | 预期效果 | 改造规模判断 |
|---|---|---|
| 工作区操作助手 | 修改框选、管理时相、修改本次参数、切换结果 | 小到中，已有逻辑可复用，但需打通意图、权限与操作回执 |
| 多时相实验助手 | 任意配对、固定基准比较、批量统计、失败组重试 | 中，需比较计划和集合引用 |
| 持续执行助手 | 整批任务执行、恢复、筛选并统一导出 | 中到大，需服务端调度、持久化与运行快照 |
| 视觉分析助手 | 看图、定位对象、辅助选区及对象级分析 | 大，需视觉输入、地理定位与专门评估 |

**建议顺序：待实施排期，未承诺。**

1. 工作区操作、确定性几何工具与明确配对。
2. 动态组合、服务端工作流、集合结果及运行快照隔离。
3. 有界实验评价与视觉能力；在前期设计中保留清晰接入边界。

这些阶段用于组织实施，不缩减已确认的整体目标。优先补齐实际能力和集合引用，比继续叠加提示词限制或单纯提高调用预算更能解决当前束缚。
