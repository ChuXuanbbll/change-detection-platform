# 瓦片加载与后端渲染

按 2026-10-12 的渲染队列、工作进程与浏览器缓存核对。地图移动与缩放期间持续加载，按动画帧合并视野更新。高清瓦片按屏内距中心的距离加载；多个保留时相及预加载共用地图队列，默认最多 4 请求，由管理配置 `browser.concurrency` 控制。

## 低清底图与空闲预加载

导入并激活时相时，优先请求覆盖该时相完整影像边界的最低两个地图级别（当前 z6、z7），每级只请求与边界相交的 XYZ 瓦片。张数取决于该时相的真实边界。底图按时相版本隔离，在高清图层下方保留已解码图像；拖动、分数缩放和缩放动画直接复用，使用浏览器平滑缩放提供低清占位，高清瓦片到达后自然覆盖。

当前视野高清瓦片全部解码且地图停止移动后，补充 z−1 视野覆盖范围及向外一圈父级瓦片，裁剪至影像范围。后台请求最多 1 个，始终计入地图总并发预算；移动或新的高清任务会取消未完成的周边预加载，已完成底图保留。高清可复用预加载 Blob，相同坐标不会同时排队两次。

每时相常驻最低两级底图，额外周边缓存最多 64 张，按最近使用淘汰；计入非活动时相缓存预算，默认 128 MiB / 3 层 / 5 分钟，可通过管理配置调整。切换和路由隐藏取消后台工作，销毁、版本失效和淘汰释放图层、请求、重试计时器及 Blob URL。预加载 503/429 最多退避重试 2 次，失败不会阻塞高清加载；409 触发目录刷新。

底图首次尚未返回、影像真实 NoData 或范围之外仍可能为空；低清底图不会生成不存在的影像。

## 后端默认限制

| 生效配置字段 | 默认值 | 范围与含义 |
|---|---:|---|
| `tiles.concurrency` | 4 | 专用常驻渲染进程，1–8 |
| `tiles.max_pending` | 8 | 不同瓦片运行＋等待总数，1–64，不能小于 concurrency |
| `tiles.wait_ms` | 1000 ms | 校验等待与渲染名额等待各自的预算，5–1000 ms |
| `tiles.handles` | 8 | 每进程数据集句柄 LRU，1–32 |
| `tiles.gdal_cache_mb` | 128 MiB | 每进程 GDAL 缓存，16–512 MiB |
| `tiles.cache_items` / `tiles.cache_mb` | 512 项 / 64 MiB | API PNG 缓存，项数 0–8192、容量 1–1024 MiB，双上限 |
| 校验入口在途上限 | max_pending × 2 | 目录校验前接纳，超限返回 503 |

日常修改通过管理页应用并持久化，字段和范围以 `backend-py/app/settings.py` 为准；已有配置不被新默认值覆盖。旧 25 ms 可按负载调整至 1000 ms，不能把历史值当新版默认。

`TILE_RENDER_CONCURRENCY/TILE_MAX_PENDING/TILE_QUEUE_WAIT_MS/TILE_DATASET_HANDLES/TILE_GDAL_CACHE_MB` 只提供首次迁移默认值；其中 max_pending 未指定时取进程数 × 2。持久化后修改这些环境变量不覆盖生效版本。默认 4 进程，调整时依据 CPU、RAM、SMB 和检测共存负载实测；当前产品面向本机单人使用。只启动一个 Uvicorn API worker，否则每个 API worker 都会复制进程池和缓存。

API lifespan 预启动工作进程并等待依赖就绪。工作进程只导入影像读取与渲染依赖，不加载 ONNX 模型。每进程同时运行一个任务，GDAL_NUM_THREADS=1，避免嵌套并行。关闭服务时等待运行中任务并显式关闭数据集；进程意外退出导致任务返回可重试 503，下次请求重建进程池。

## 接纳、取消与重试

API 先在单独、受限的校验线程取得目录快照与版本，再在事件循环中查成品缓存、合并相同任务、等待执行名额。只有取得名额的任务才提交到进程池，不在进程池内部堆积长队列。校验和渲染的等待预算分别计算，因此默认 1000 ms 并非整个请求的截止时间，也不是 GDAL 原生 I/O 的执行超时。

同一瓦片共用一个任务，一个客户端断开不会取消其他客户端需要的任务。所有等待者离开且任务尚未提交时取消任务。已进入 GDAL 的工作继续占用名额直到完成，即使请求被取消；产物可进入有限缓存供后续请求使用。

前端取消过期 fetch，Vite 转发瓦片响应连接关闭给 Python；后端约每 10 ms 检查等待者是否断连。对端断连检查不能中止已经开始的原生 I/O。

队列超限或等待超时返回 `503`、`Retry-After: 1`、`Cache-Control: no-store`。前端对 503/429 最多重试 4 次，采用指数退避、服务器 Retry-After 秒数与少量随机延迟，等待时释放地图调度槽位；时相切换、暂停、移出视野和销毁会清理重试计时器。409 不重试，继续触发目录更新。

## 数据集、版本与画质

数据集只在所属工作进程中使用，不在 API 线程、进程或检测裁剪之间共享。LRU 按路径、源版本和概览层建立键；源版本变化会关闭旧句柄，淘汰、读取失败和退出也会关闭句柄。目标 WarpedVRT 仍逐张创建。

目录快照及刷新代数在同一锁下取得。刷新代数参与父进程 PNG 缓存键；工作进程收到新代数后清理句柄、参考分辨率和边界缓存，再使用父进程传来的场景快照，避免各进程独立扫描 NAS 或保留旧目录。版本校验在成品缓存命中前执行，失效时相仍返回 409/no-store。旧代数缓存项不可被新代数请求命中，并受总内存和项数上限淘汰。

默认 PNG 编码、原有双线性重采样、透明通道与边界裁剪保持一致。原有同步 `render_tile` / `render_mosaic` 保留用于脚本和回归；HTTP 渲染走进程池，检测裁剪继续使用原始分辨率读取。

“PNG 未缓存”与“源数据完全冷”不同。句柄和数据块未预热时，首次访问新概览层仍可能出现数百毫秒尖峰。有界队列保护系统资源，不保证所有负载下的单瓦片延迟；过载由前端退避恢复。没有默认降低 PNG 压缩级别，也没有引入 GPU 瓦片计算。

## 观测与验证

成功响应的 `X-Tile-Cache` 为 `hit`、`miss` 或 `shared`。

`Server-Timing` 包含：

- `tile_prepare`：目录校验及其线程等待时间。
- `tile_queue`：该共享任务创建到提交的等待时间。
- `tile_render`：提交到返回的墙钟时间，包含进程通信。
- `tile_compute`：工作进程内部渲染时间。
- `tile_total`：本次 HTTP 处理中的校验、等待及取结果时间，不含响应传输。缓存命中时 render/compute 为 0；共享任务的 queue/render 是原任务值，不应与后加入请求的 total 相加。

主要回归：

- `backend-py/tests/test_tile_queue.py`：并发上限、断连、运行中取消、队列超时、单任务合并、异常、版本和内存上限。
- `backend-py/tests/test_tile_worker.py`：独占句柄复用、淘汰/失败关闭、真实 spawn 像素对照、刷新、过期版本、进程崩溃恢复及关闭。
- `backend-py/tests/test_tile_metadata.py`：元数据并发复用与版本失效。
- `scripts/test_tile_retry_browser.mjs`：503/429 恢复、Retry-After、尝试次数上限、暂停取消和 409 不重试。
- `scripts/test_tile_scheduler_browser.mjs`、`test_phase_cache_browser.mjs`：移动中加载、当前视野优先、相位缓存与资源生命周期。
- `scripts/test_tile_preload_browser.mjs`：全范围最低两级、空闲周边加载、移动抢占、低清占位、复用与资源释放。
- `scripts/test_tile_proxy.mjs`、`test_imagery_workspace_browser.mjs`：代理断连和业务页面回归。

Windows 后端全套回归应在 `backend-py` 目录执行 `python -m unittest discover -s tests -v`，并设置 `LOCAL_IMAGERY_DIR` 为项目 `data/imagery` 样例目录。性能验证使用真实 Y 盘影像。浏览器脚本支持 `PLAYWRIGHT_MODULE`、`FRONTEND_URL` 与 `BROWSER_OUTPUT_DIR`。
